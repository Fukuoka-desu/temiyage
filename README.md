# 手土産えらび

全国の名品から、贈る相手の出身地・好み・時期・用途・関係・予算に合う手土産を選ぶ静的Webアプリです。Vite + React + TypeScript、システムフォントとローカルデータのみで動きます。

## 使い方

条件パネルで土地・好み・人柄・予算・贈る時期と場面を選ぶと候補が更新されます。好みは複数選択でき、いずれかに合う品が候補になります。産地・ジャンル・キーワードでさらに絞り込み、並べ替えができます。最初は24件表示し、「もっと見る」で24件ずつ追加します。スマートフォンでは条件を折りたたみ、「候補を見る」で結果へ移動できます。

「この条件を共有」で、全条件を含んだURLをコピーします。クリップボードが使えない環境ではURL欄から手動でコピーできます。「条件をリセット」で初期条件へ戻せます。

おすすめ順は確認済みの品を先に並べ、その中で条件のスコアが高い順、同点では価格の安い順です。他の並べ替えも確認済みを優先し、その中で指定した順になります。予算「指定しない」（`budget=any`）は全価格帯と価格不明を含み、予算の加点はしません。予算帯 b1〜b4 では「価格不明の品も含める」（既定オフ、`pu=1`）で価格不明も含められます。どの並び順でも価格不明は価格のある品のあとに表示し、それぞれの中で確認済みを優先します。両条件は共有URLに保存し、budgetのない旧URLや不正値は従来のb1になります。日持ち不明は「日持ち重視」でも含み、日持ち順では末尾に表示します。価格帯の近傍（下限の80%〜上限の115%）の品も候補に含みます。

## 開発・検証

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

`dist/` に静的ファイルが生成されます。Viteのbaseは `./` で、サブディレクトリにも配置できます。ビルド成果物・node_modulesはコミット対象外です。実行時の外部通信は商品リンクのクリックのみで、ログイン・個人情報の入力・アクセス解析・外部フォント・外部CDNはありません。

## データの出典と更新

唯一の元データは `/workspace/temiyage/temiyage_master.csv` です。収録件数・都道府県数・確認済み件数・確認日は生成データから表示します。各カードに元データの出典リンク・種類・確認日を表示します。価格・内容・販売状況・日持ちは購入前にリンク先で確認してください。日持ちの起算日は出典により異なります。

`npm run build` のprebuildで、毎回CSVから商品JSONと印を生成します。手動更新は以下を実行します。このアプリで品の追加・削除や値の訂正を行うことはありません。

```sh
npm run data
# 別の配置のCSVを指定する場合
TEMIYAGE_CSV=/path/to/temiyage_master.csv npm run build
npm run typecheck
npm test
npm run build
```

生成した `src/data/items.json` も管理対象です。変換は数値の型変換、空の数値のnull化、タグの配列化、個包装・確認状況の真偽値化、保存方法の表示ラベル生成を行います。保存方法と日持ちは原文も保持します。元CSVは変更しません。

スコアは `src/lib/score.ts`、URL条件の検証・復元は `src/lib/url.ts` に分離しています。

テストはNode.js標準の `node:test` を使います（Node.js 18以上）。この作業環境ではnpmレジストリの名前解決ができずvitestを取得できなかったため、追加依存なしでスコアとURL復元を検証しています。テスト対象のTypeScriptは既存のTypeScriptで一時的に変換し、テスト後に削除します。

## 時期・用途と注意

時期は季節を問わない・お中元（夏）・お歳暮（冬）・お年賀、用途はお礼・お詫び・ご挨拶と訪問（既定）・お祝い・お見舞い・帰省や旅行のおみやげ・職場への差し入れです。相手との関係は指定しない・取引先や目上の人・気軽な相手から選びます。こちらの土地は未指定なら東京として扱います。

URLの`season`と`use`に保存し、旧URLの`use=first`は`visit`へ読み替えます。不正値は既定に戻します。結果上の「いまの条件」は0件時や共有URLの復元時にも表示します。

印は指定された7列だけからルールで生成し、`data/marks/mark_rules.csv`に条件、`item_marks.csv`に各品の根拠を出力します。夏の保存、お詫びの嗜好、お見舞いのお酒や日持ちには黄色の注意を表示します。注意だけでは候補から除外しません。既存の日持ち重視などの絞り込みは適用されます。

確認状態列があれば優先し、なければ判定列で確認済みを判定します。公式URLは表示用にHTTP(S)だけを採用し、無い品はリンクボタンを表示せず「公式ページの情報がありません」と表示します。CSVの値は変更しません。

両生成スクリプトは外部の元CSVがあれば `data/source/temiyage_master.csv` にバイト単位でコピーしてから読みます。無ければこのコピーを使用します。`TEMIYAGE_CSV` で入力を上書きできます。元CSVの値は変更しません。

## 商品画像URLの収集

Python標準ライブラリのみで、公式ページのメタ情報から画像URLを収集します。

```sh
python3 scripts/fetch_images.py
python3 scripts/fetch_images.py --resume
python3 scripts/fetch_images.py --limit 10
python3 scripts/fetch_images.py --only-ids 1,2,3
```

入力は `src/data/items.json`、出力は `data/images/item_images.csv` と `data/images/summary.md` です。指定なしでは全品をid昇順で出力し、絞り込み時は対象品のみ出力します。実行ごとに出力を上書きします。`--resume` は保存済みページキャッシュを再利用し、画像の到達確認は再実行します。キャッシュは `data/images/cache/` に保存します。共通画像の判定範囲は実行対象の出典ページです。全体最大6並列、同一ホストは直列かつ最低2.5秒間隔でアクセスします。元データは更新しません。
